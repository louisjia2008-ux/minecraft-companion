# 新执行核心

与 `vendor/server/minecraftTaskAgent.js` 并行开发的新核心，还没有接入桌面应用。目前先通过场景测试平台在真实 vanilla 1.21.8 服务器上单独验证，稳定后再逐项替换旧代理的能力。

## 核心规则

1. **身体只有一个决策点。** `brain.js` 每轮（250ms，或上一个动作结束时）重新读取世界状态，按优先级选出一个行为执行。优先级从高到低：逃离 130 > 防御 120 > 维持（进食、回血、找食物、捡回掉落物）100 > 目标 50。高优先级行为出现时，当前行为通过 `AbortSignal` 被中止，等它真正停下后才启动新行为。同一优先级内不互相抢占。
2. **任务不"恢复"，只重新判断。** 目标只提供 `isDone(state)`、`progress(state)`、`run(ctx)` 三个函数和一个名字。进度保存在世界里（背包、已放置的方块），不保存"做到第几步"。被打断后，包括死亡后，下一轮看现状重新决定，不需要任何恢复分支。
3. **动作要短，并且以服务端事实为准。** 每个动作都有秒级超时，能响应中止，只在观察到实际结果后才返回 `ok`。进食要求"食物数量减少"和"饱食度上升"同时成立。熔炼的产物在关闭熔炉界面后才计数，因为 Mineflayer 只在界面关闭时同步背包。
4. **失败就换目标，不修路线。** 失败的目标进入短期黑名单，下一轮选择别的目标。连续多次找不到路时，执行一次"脱困"：在地下就垫方块爬回地面，否则走出去或往下挖。
5. **不会无限重试。** 目标连续多次没有进展，就以 `goal_failed` 结束并附带原因；每次失败后会短暂暂停再试。被生存行为打断不算"没有进展"。
6. **身体出问题由通用恢复处理，不归目标管。** `behaviors/recovery.js` 对所有目标一视同仁（维持优先级，生存反射仍然优先）：
   - **卡住**：目标连续 2 次寻路类失败，或目标失败且 45 秒内移动不到 2 格，就执行脱困。
   - **掉坑**：脱困时手里垫脚方块不足 4 块，先挖坑壁拿泥土或圆石再垫；还上不去就斜着挖台阶，挖台阶从不碰与水、岩浆相邻的方块。
   - **背包满**：空格不超过 1 个时，家里箱子在 48 格内就存进去，否则丢弃垃圾（沙砾、燧石、安山岩、腐肉等）和超出一组的泥土、圆石，丢完走开 6 格以免捡回。工具、食物和目标通过 `bot.companionKeep(name)` 声明要的东西不丢；没东西可丢时不触发。
   - **死亡循环**：10 分钟内在 24 格范围里死 3 次，这里就算危险地点：白天先往水少的方向走出 48 格，晚上就地挖地堡等天亮；那里的掉落物也不再回去捡。1 小时内死超过 8 次，目标以 `death_loop` 失败结束。掉落物回收的距离按"消失前走得到"计算，最远 600 格。

## 完整任务链：`goals/homestead.js`

从空背包到"装备 + 一栋家具都实际用过的小屋"。`planner.js` 是纯函数：每一步根据背包和已放好的工作台、熔炉，算出唯一的下一步动作。顺序如下：

1. 选址（`site.js`），整地（只处理一格高的凸起和凹坑）。
2. 石剑、石镐，然后储备 4 份食物。
3. **床**：做好后直接放到房子里预定的位置。从第一个夜晚起就能睡觉跳过夜晚，重生点也设在家里。
4. 房子（`blueprints/starterHouse.js`）：7×7、墙高 2 格（门正好 2 格高，机器人身高 1.8）的圆石墙、木板屋顶、门、火把、箱子、熔炉。材料攒够一批（16 块）再回家施工，开始施工后一直放到这批材料用完。
5. 铁剑、铁镐、盾牌（挖铁 → 在家里的熔炉烧铁锭）。
6. 实际使用每件家具：箱子存物、床（睡觉或设重生点）、工作台合成、熔炉熔炼。

### 在真实服务器上发现并已修复的问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 屋顶第一圈、墙最上一层放不上去 | 它们要放在下方方块的上表面上，而这个面高于站在地上时的视线，原版不允许点看不到的面 | 墙改为 2 格高，每块墙都能从地面放；屋顶从屋中间的 1 块泥土台阶上铺，外壳完成后台阶作为"障碍"被整地规则自动拆除 |
| 卡在房子旁边的坑里出不来 | 绝对禁止挖掘房子区域，坑的一侧正好是禁区 | 改为"挖掘代价高"而不是禁止；被挖掉的墙或地基会被构建检查自动补上 |
| 在房子正下方采石后被困 | 采集目标落在房子下方 | 房子所在的整个竖直柱体都不作为采集目标 |
| 爬不出矿井或采石坑 | 不允许垫方块 | 低于房子地面高度时允许用泥土或圆石垫高，在地面上从不垫 |
| 重生在树冠上走不下来 | 下落限制 3 格 | 下落上限放宽到 4 格；仍走不了就触发脱困 |
| 做了两把石镐、两把铁剑 | 规划器把"已满足的工具要求"当成消耗 | 工具只检查、不扣减 |
| 熔炼成功却报"没有产物" | 熔炉界面开着时不同步背包 | 关闭界面后再计数 |
| 盾牌放进副手后又去做新盾牌 | `inventory.items()` 不含副手栏和盔甲栏 | 统一用 `ownedItems()` 计数 |
| 一次失败的合成在 1 秒内重试 25 次 | 背包计数与服务器不一致，规划器以为材料够 | 合成失败时报告具体差多少，作为临时需求补齐；目标失败后短暂暂停再试 |
| 木板不足却持续合成箱子；下一轮清空背包后仍尝试合成木棍 | Mineflayer 4.37.1 把 `set_player_inventory` 的玩家库存下标当作窗口下标，退还合成材料时把热键栏木板写进靴子栏；`ownedItems()` 因而重复计数，`clear` 也清不掉客户端的幽灵装备 | 新核心为 1.21.8 + 此依赖版本转换槽位坐标；合成中止先停止后续点击，等原操作结束再关闭窗口；返回合成格与光标物品后才重新规划；短缺只按主背包中的可合成材料计算 |
| 2×2 合成中止后实际材料已退回，仍认为光标上有物品 | 同一依赖忽略 `set_cursor_item` 和窗口同步的 `carriedItem` | 仅在关闭合成界面、原点击已结束的确认阶段同步服务端光标；普通装备/点击流程保留原生预测，避免延迟旧包覆盖后续点击 |
| 选址选在山坡上，一直在挖山 | 选址时区块未加载完，空值被当作空气 | 未加载视为未知，不选；净空空间里的实心方块都计入工作量；整地超过 40 块就换地方 |
| 夜里被骷髅、苦力怕、蜘蛛打死 | 先做铁装备，房子来不及盖 | 改为"石器 → 食物 → 床 → 房子 → 铁"，天黑就去睡觉；血量高于 14 才主动追打骷髅 |
| 低血量时还跑去远处打猎而死 | 没有低血量策略 | 血量低于 10 时禁止远行打猎；敌人不在 4 格内就先吃；吃饱后原地回血；死后 5 分钟内回去捡掉落物 |
| 平地测试世界里被史莱姆刷死 | 平地世界地表在 y=1，低于 y=40 的史莱姆区块全天刷史莱姆 | 测试世界地表抬到 y=64，世界出生点固定在空地上 |

### 自然地形上发现并已修复的问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 一直吃不饱，最后饿死 | 动物在湖对面过不去；追远处的动物时，动物走出追踪范围也被算成"打死了" | 允许游泳，远路分段走；只有亲眼看到死亡（或在身边打过后消失）才算击杀；附近 16 格有动物且食物不足 10 份时顺手打猎囤粮 |
| 山谷里砍树后卡死不动 | 只要低于房子地面高度就算"在地下"，一直想往上爬 | 头顶是露天就不算在地下；爬出失败后先做别的事 |
| 淹死在自己挖的坑里 | 挖了紧挨着水的石头，坑被淹，上方又被挡住 | 不挖与水或岩浆相邻的方块；缺氧时把头顶的方块挖开 |
| 死后空手过夜，在出生点卡住 | 挖地堡要求背包里先有封口方块 | 竖井本身挖出的泥土、圆石就用来封口 |
| 沙漠里没法挖地堡，一直重试 | 沙子周围不能挖竖井 | 房子外壳已完成（还没门）就进屋，用泥土堵住门口过夜；找不到地堡位置就继续干活 |
| 61 次放墙失败 | 把门当成了放置的依靠面，右键只会开关门 | 门、箱子、床、工作台等能交互的方块不作为依靠面 |
| 床一直做不出来 | 羊毛颜色混杂（2 白 1 灰）；附近根本没有羊 | 优先打颜色最容易凑齐的羊，跳过剪过毛的羊；没有羊时打蜘蛛，4 根线合成 1 块白羊毛 |
| 木板够数却合成失败 312 次 | 配方要求同一种木板，2 块白桦 + 1 块橡木不能合成 | 木板只按数量最多的那一种计数 |
| 被末影人打死（最常见的死因） | 石剑打不过，末影人还会瞬移 | 发现愤怒的末影人就挖 1×1 竖井封住躲进去，等它走开再出来 |
| 掠夺者前哨站旁边反复被打死 | 前哨站会持续刷掠夺者 | 不和掠夺者交战，远离它们；记住出现位置，80 格内不建房，刚开工的房子直接换地方 |
| 赤手追骷髅掉进洞里 | 看到骷髅就追 | 只有带着剑或斧、且高度差不超过 4 格时才追 |
| 黑森林、苍白之园里不停死 | 树冠遮光，白天也刷怪 | 选址时拒绝被树冠覆盖的地点 |
| 死后在 400 格外的出生点复活，来回跑 | 还没有床，复活点在世界出生点 | 如果房子刚开工（不到 30%）且没有床，就在复活地附近重新选址 |
| 在山顶房子 40 格外反复超时 | 放置方块的寻路很短，离得远就超时 | 目标超过 12 格时先分段走回去 |
| 卡在高处的悬空原木上 | 树干下半截砍完后，上面的原木够不着 | 悬空原木排在最后；一次够不着就跳过整棵树 |
| 附近树砍光后一直在家附近绕圈 | 每次探索随机换方向；只在 48 格内找 | 探索沿同一方向走，被挡住才转向；先在 128 格内找，远的目标分段走过去 |
| 天黑后从远处赶路回家被打死 | 傍晚才往回走，路上已经天黑 | 天黑时离家超过 64 格就原地挖地堡过夜 |
| 一类问题卡住整个任务 | 连续没有进展就永久失败 | 进展预算用完后先"恢复"：清空黑名单、脱困、走回家，再给一轮预算，最多 6 次 |

## 下界：`goals/netherQuartz.js`

- **搭门**：门框底排放在地面上，四角先放圆石，侧柱压在底角上、顶排贴着顶角放，所以不需要点击视线以上的方块面。看到门内 6 格都变成传送门方块才算点燃。
- **进出**：走进门、停下，等服务器切换维度（以 `bot.game.dimension` 为准），等区块加载后走出门。两边门的位置都记住；死在下界后在主世界复活，目标重新判断：走回门、再进去。
- **防岩浆**：下界寻路时，站在岩浆、火、岩浆块上或其上方代价 1000，旁边有岩浆每侧 +60，旁边是通向岩浆的落差 +30；下落上限 3 格；不挖金矿、镶金黑石、箱子、黑曜石和传送门（挖金会激怒猪灵）。采集本来就跳过与液体相邻的方块。
- **恶魂**：能看到机器人头部的恶魂在 48 格内时，找附近头顶有遮挡、恶魂看不到的位置躲进去；找不到就挖竖井封顶。躲完 10 秒内不再躲，避免一直躲着不干活。飞近的火球用剑打回去。
- **猪灵**：僵尸猪灵（以及戴金头盔时的猪灵）不当作威胁，不会因为它们在旁边就停止吃东西或主动攻击；只有被它们打了，才把同一群（24 格内）当作敌人 60 秒。
- 下界里不打猎找食物、不用床（`useBed` 直接拒绝）；死亡掉落只在同一维度时回去捡。

## 自主发育：`director.js`

没有玩家任务时，机器人自己决定下一步做什么。默认关闭，`companion.setAutonomy(true)` 或 `createCompanion({ autonomy: true })` 打开。

1. **调度器不动身体。** brain 空闲 3 秒后，调度器读一次世界状态，给 `goals/registry.js` 里的每张卡片打 0–100 的需求分，把最高分的目标交给 brain。全是 0 分就继续待机。
2. **跑完才重选。** 目标运行中不重新打分，结束（完成或失败）后才选下一个，避免来回切换。
3. **风险看时间和身体。** 卡片标 `low` / `medium` / `high`。夜里 `medium` 只算 40%，`high` 不选；血量 < 12 或饥饿 < 8 时 `medium` 算 60%，`high` 不选。
4. **失败冷却。** `goal_failed` 的卡片冷却 5 分钟，连续失败翻倍，上限 1 小时；完成一次就清零。
5. **玩家优先。** 玩家下的任务直接替换调度器的目标；玩家任务结束后等 30 秒再恢复自主。玩家 `stop()` 同时关闭自主。
6. **阶段从世界算出。** 0 = 家还没完成；1 = 房子、家具、铁装都齐。死后丢了铁装会回到阶段 0，重新补齐。

现有卡片：`homestead`（阶段 0，整个运行只用一个实例，所以一直接着建同一栋房子）、`stock_food`（阶段 1，食物少于 16 个时打猎）。新目标要加入自主发育，只需在 `registry.js` 里加一张卡片：`{ id, stage, risk, requires?, need(state, memory), create(memory) }`。

每次选择会发出 `autonomy_choice` 事件，附带所有卡片的分数和被跳过的原因（`stage` / `requires` / `cooldown`），方便调参。

## 真实服务器测试结果（vanilla 1.21.8，easy 难度，昼夜循环和刷怪开启，空背包开局）

| 场景 | 结果 | 说明 |
|---|---|---|
| `collect-logs-flat` | **20/20 通过** | 中位用时 41 秒，0 次死亡 |
| `homestead-flat` | **9/10 通过** | 两格高墙之后共 10 次：早期 8 次里 7 次通过（唯一失败是"烤肉"功能的 bug，已修）；用最新代码回归 2/2 通过，用时 37 和 70 分钟，共死亡 1 次 |
| `homestead-natural` | **6/10 通过**（最终测量） | 10 个随机地点（每次距离出生点 400～2000 格），空背包开局，easy，150 分钟超时。通过的 6 次用时 35～72 分钟，中位约 37 分钟，全部检查由服务器确认。4 次失败：①木板种类混杂导致床合成失败（测量期间已修）；②附近树砍光后在家附近绕圈、死后丢了铁剑（测量期间已修：128 格搜索 + 定向探索）；③天黑后从远处赶回家，一夜死 12 次（测量期间已修：天黑离家远就地挖地堡）；④世界出生点在海边，复活后反复被溺尸杀死（未解决）。在此之前，中间版本的一批里跑完的 5 次全部通过（另 1 次在苍白之园里被中途停掉） |
| `nether-quartz-given` | **10/10 通过** | 开局给 10 块黑曜石、打火石、铁镐铁剑、熟牛肉、金头盔；平地主世界搭门点火，进入自然生成的下界，在到达的门 96 格内采 16 个下界石英后原路返回。服务器判定石英数量和所在维度。中位用时 100 秒，0 次死亡；2 次躲恶魂 |
| `night-bunker-flat` / `night-bed-flat` | 通过（较早版本，最新代码未重跑） | 黄昏开局：能睡就睡；睡不了就挖地堡过夜，第二天爬出来继续干活 |

### 尚未解决

- **复活点危险时会陷入死亡循环**：没床之前死在世界出生点复活，若出生点在海边或刷怪多的地方会反复死亡。可考虑：复活后立刻远离水边、在出生点附近先挖地堡。
- **深处挖矿仍会死**：在 y<30 的洞穴里找铁时，偶尔被包围。可考虑：只挖靠近地表的矿，或者挖矿前先做铁剑以外的防护（盾牌已有，但出现得较晚）。
- **长期食物**：现在靠打猎和囤粮，没有种田或繁殖。超过一两个游戏日的长时间陪伴需要补上。
- **自然地形差异大**：需要更多次运行才能得到稳定的通过率；最终测量期间加的 3 个修复还没有经过完整的 10 次测量。
- 还没有接入桌面应用和 AI Provider。

## 测试

```bash
npm run test:core     # 单元测试，包括在模拟世界里跑完整任务链（带随机失败和中途死亡）

# 真实 vanilla 服务器场景（Java 和 server.jar 默认取自 .minecraft-local-test/installation.json）
npm run scenario -- --accept-eula --scenario collect-logs-flat --runs 20
npm run scenario -- --accept-eula --scenario homestead-flat --runs 3
npm run scenario -- --accept-eula --scenario homestead-natural --runs 3

# seed=500 的第 4、5 轮地点；同一服务器、世界与玩家，只改变客户端生命周期。
# 默认 reuse；fresh 在每轮验证完成后断开并重新建立 Mineflayer bot。
npm run scenario -- --accept-eula --scenario homestead-natural --seed 500 --start-run 4 --runs 2 --bot-lifecycle reuse --inventory-trace
npm run scenario -- --accept-eula --scenario homestead-natural --seed 500 --start-run 4 --runs 2 --bot-lifecycle fresh --inventory-trace
```

`--inventory-trace` 在单轮日志中额外记录主背包、装备栏、合成格、光标、当前窗口与库存数据包；出现 `missing_ingredients` 时每分钟最多读取一次服务器库存。它只读服务器状态，不补给材料或干预目标。`--start-run` 保留原轮号对应的随机种子和地点中心；原版 `spreadplayers` 的落点、动物与战斗并不由该种子完全决定，不能保证逐帧重放。

复用 bot 时，每轮 `companion.dispose()` 也会移除该轮生存行为的死亡监听，避免旧监听随轮数累积。每轮结束会取消尚未到期的场景计时器，结果写完并停服后进程可自行退出。

结果写入 `.minecraft-local-test/scenario-runs/<批次>/<场景>/`：每次运行一个 `run-XX.jsonl`（setup 参数、每个决策事件、每分钟一次心跳、最终结果），加上一个 `summary.json`。是否通过一律由服务器判定：
- 物品数量：用 `clear <玩家> <物品> 0` 计数，不实际清除。
- 房子：逐块执行 `execute if block` 检查。
- 箱子：用 `data get block` 读取箱子内容。
- 床：读取玩家的 `respawn.pos`，必须正好在床上。
