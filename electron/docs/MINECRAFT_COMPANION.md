# Minecraft 陪玩 / Minecraft companion

Minecraft 陪玩位于 Electron 控制台左侧的“陪玩 / Minecraft”。它使用迁移自 `live2d-mc-companion` 的 Mineflayer 执行引擎，在独立子进程中连接 Minecraft **Java 版**服务器。无需导入 Live2D 模型即可使用陪玩控制台；桌面角色继续使用 DeskPet 当前的模型。

## 使用

1. 启动 Minecraft Java 服务器，或在 Java 单人世界选择“对局域网开放”，记下显示的端口。默认服务器端口是 `25565`；局域网世界的端口可能每次不同。
2. 打开 DeskPet Electron → 陪玩，填写服务器主机、端口、机器人玩家名称及你的游戏玩家名称。版本默认 `auto`，可指定与服务器一致、Mineflayer 支持的 Java 版本。
3. 离线认证适用于允许离线身份的服务器。启用正版认证的服务器需要 Microsoft 登录；选择 Microsoft，输入账号标识，按页面显示的官方验证网址和设备码完成登录。机器人需要使用获准加入服务器的账号；在线玩家与机器人通常需要各自的账号。
4. 默认“规则模式”直接使用原项目的任务解析与技能，不调用 AI。选择“混合模式”时必须明确选择一个已启用的 DeskPet AI Provider；任务规划会使用这个模型，并可能产生该服务的调用费用。
5. 点击“连接”。“连接中”表示登录或世界初始化仍在进行；实际出生并收到状态后才显示已连接。可随时点“断开”取消连接或认证。
6. 输入任务，例如“跟着我”“挖 10 个圆石”“收集 16 个木头”“从零开始挖到 1 个钻石”。能否执行取决于服务器权限、附近资源、背包和原引擎技能。通过当前任务、日志和背包观察实际结果。
7. 可暂停、恢复、取消任务，或点击停止动作；刷新会读取真实运行时状态。聊天框发送普通游戏聊天，不接受 `/` 服务器命令。

机器人会在 Minecraft 世界内移动、挖掘或放置方块。建议先在测试世界验证任务行为。应用不会在启动时自动入服、自动启用自主任务或调用模型；退出应用或断开连接会终止陪玩进程。

## 开发与验证

```bash
cd electron
npm ci
npm run test:minecraft
npm run verify
npm run test:e2e
npm start
```

`npm ci` 的 postinstall 会根据独立锁文件安装 Minecraft 生产依赖，关闭依赖安装脚本。若主依赖安装使用了 `--ignore-scripts`，补运行：

```bash
npm ci --prefix minecraft-runtime --ignore-scripts
```

打包时 `prepare:minecraft` 把运行时和生产依赖放在应用资源目录的 `minecraft-runtime/`，保留 Node 包结构并排除测试、模型、压缩包。运行时使用 Electron 自带 Node，不要求用户额外安装 Node。Minecraft 的协议与方块数据会增加安装包体积。

## 迁移结构与数据边界

- `minecraft-runtime/vendor/`：原项目的任务引擎、动作注册、认知/查询模块、Minecraft 子模块和规则文件。`PROVENANCE.json` 记录实际迁移文件的 SHA-256；原目录含未提交修改，不能把它描述成某个干净提交的完整导出。
- `minecraft-runtime/`：DeskPet 的独立进程适配、严格 JSONL 输入、连接生命周期和测试。迁移未携带原项目的 Electron/Vue 界面、Express/WebSocket 服务、Live2D SDK、模型、私人配置、聊天记录或认证缓存。
- `src/main/minecraft/`：主进程拥有唯一陪玩服务，验证进程消息并投影有界状态。所有控制 IPC 只允许 Console 窗口调用；renderer 无 Node 或通用 IPC 权限。
- `src/renderer/console/MinecraftPage.tsx`：英文/中文的连接、任务、背包、聊天和状态界面。
- AI 请求通过已有 Provider utility process 执行。Minecraft 子进程只接收提示与规划结果，不接收 Provider API key、Provider URL 或通用工具执行能力。
- 游戏学习和 Microsoft 认证缓存保存在 Electron 独立用户目录下的 Minecraft 子目录；不读取原项目的数据，也不与原生 DeskPet 共享目录。Microsoft 认证缓存属于敏感本机数据，不应提交、复制到报告或加入安装包。

## 支持范围与验收边界

Java 版的实际兼容版本以锁定的 Mineflayer 和 minecraft-data 为准。Bedrock 版未接入。原项目的实验协议补丁保留来源记录，不作为新版本支持承诺启用。固定依赖中已确认的 1.21.8 鸡变种 metadata 解析错误，采用当前客户端专属且精确限定版本与错误 schema 的兼容修复，不改全局协议数据。

本次接入提供桌面任务指令、引擎技能、状态/聊天同步与模型辅助规划。原项目的 Vue 聊天界面、Telegram、TTS 和全局聊天记忆仍由 DeskPet 各自现有功能承担；它们未作为第二套应用迁入。游戏聊天不会自动触发 AI 回复或接管任务。

本地单元测试、进程测试和打包测试只证明对应合同。真实 Minecraft 世界内的寻路、采集、建造、服务器插件兼容，以及 Microsoft 登录和真实云端 Provider，需要在对应环境验证；Windows/Linux 实机验收也需在各平台进行。不得用 fixture 或 macOS 构建结果替代这些证据。

## 原引擎逻辑复查 — 2026-10-12

用户补充旧项目能够进服，但任务执行到一半会卡住。随后对迁入的执行逻辑做了定向复查，发现原项目已有的缺陷，不能用迁移接线测试代替这些逻辑检查：

- 实体识别仍假设怪物类型是 `mob`、掉落物是 `object`。锁定依赖的现代 Java 数据中，普通怪物使用 `hostile`、掉落物使用 `other`，原筛选会漏掉它们。现在按实体名称和 registry 语义判断，并排除箭、船等其他实体。
- 拾取逻辑把目标中心转换成普通 `{x,y,z}`，后续又调用仅 `Vec3` 才有的 `distanceTo()`。这会在执行中抛错；现改为对两种坐标表示都适用的有限数值距离计算。
- 持续跟随/护卫套用了有限任务的硬超时。现在健康的持续动作不因达到固定时长而中断，仍保留无心跳/无进度的停滞检测和有限步骤超时。
- 移动监视器把“曾经移动成功”一直当作稳定跟随，目标远离且机器人卡住后仍可能伪造健康状态。现在只在当前目标范围内允许原地等待，范围外失去物理进度仍触发恢复。
- 护卫准备引用未定义的 `PICKAXE_ITEM_PRIORITY`，空手或没有斧头时会在装备判断中抛出 `ReferenceError`。现使用实际导入的工具列表，并把迁入引擎的未定义变量检查加入 `npm run lint`。
- 指定玩家不在视野内时，原查找会退回最近的其他玩家。现在明确目标缺席时不替换目标；DeskPet 也不再把最近的陌生玩家默认为主人。
- 自然语言解析中，木材关键词抢先于合成、取箱和建造，`craft wooden_pickaxe`、从箱子拿木头、`build a wooden house` 会被当成砍树；另遗漏“去 10 64 -5”和大写 `FOLLOW ME`。解析器已独立出来修正优先级，并用实际 action registry 验证指令及参数。
- Electron 手动断开后遗留旧背包/生命值，以及重连后任务编号重复导致完成气泡不再出现，属于本次接入层缺陷，已清理状态并修正连接间的去重范围。
- 死亡或切换世界后，原适配层仍允许接收任务。现在保留网络连接但撤销世界可执行状态、取消旧动作和规划；收到新 `spawn` 后重新初始化，旧计划不会自动恢复执行。
- 引擎在断开或离开世界时虽已结束真实任务，前景快照却可能保留旧的 `planning` 副本，让界面看起来仍在规划。现在同步终态快照，任务结果不会被过期副本覆盖。

回归测试使用锁定的 `minecraft-data`、`prismarine-entity` 和物品 metadata，并覆盖实际引擎的规划、分派及取消路径。AI 闭环测试使用明确标记的模拟 Provider 和模拟物理世界，不调用云端模型。上述缺陷能解释部分中途失败路径，但没有旧失败会话日志，不能判定它们就是当年那次卡住的唯一原因。

用户进一步说明问题集中在“从零挖到钻石”和“收集材料再造房子”。追加复查复现了多步骤执行链的目标丢失、材料预算、合成数量和熔炉进度问题。本地修复与验证覆盖以下行为：

- 某一步失败后的修复计划保留原始目标和后续未完成步骤。修复石镐不能删掉后面的铁镐、钻石或返程；钻石恢复不能误选前置链中的第一条煤矿任务。
- 学习计划以当前任务的资源、物品和步骤顺序为准，避免复用同类动作时把采金矿改成旧的采铁矿目标。
- 小木屋材料按世界中的实际缺口计算：默认结构 31 块，另计地基支撑；已有地板和墙体不再重复计入预算。回到清场阶段时，符合本蓝图的墙顶会保留；地板高度的泥土、石头等障碍会先清理，避免后续铺地板持续报占用。
- 小木屋最终校验缺块时重新准备缺少的材料并执行修补阶段，不能只重复校验。测试在内存世界中删除一块屋顶后，真实执行引擎会补上它并通过最终检查。
- 合成木板、木棍按实际目标数量完成，区分输出物品数和配方执行次数。工具前置链按真实背包补足所需材料。
- 熔炼按目标还差多少计算原料，承认燃料槽为空但炉内仍在燃烧的状态；真实熔炼进度和物品变化会更新心跳，长期不变仍会报停滞。
- 运行中暂停、恢复和取消保持控制状态；寻路因暂停而结束后，不得进入普通失败恢复自行重启。物理复位计数与任务恢复预算分开，一次失败不会消耗两次计划恢复机会。

上一轮新增 35 项回归，包括房屋进度与返程 12 项、材料与熔炼 11 项、目标与恢复完整性 10 项、执行中暂停 2 项。上一轮冻结版本的完整运行时测试为 116/116 PASS；本轮开矿功能的最新结果见下方验证表。在已有可达矿物和工作台/炉子的模拟世界中，真实引擎、已安装 Mineflayer 配方与采掘等级数据贯通“空背包 → 工具 → 铁矿 → 木燃料熔炼 → 铁镐 → 附近钻石”；该测试未替代实际 Minecraft 世界验收。

## 从零开始挖到钻石

规则模式和混合模式均可直接输入 **“从零开始挖到 1 个钻石”** 或 **“mine 1 diamond from scratch”**。这类已识别的钻石指令在两种模式下都使用内置远征，不需要调用云端模型。钻石采集任务现在进入专用远征流程；它保留原始数量目标和后续任务，只有背包实际收到目标钻石且沿已检查的矿道返回，才报告开矿完成。

流程依次准备木材和备用木棍，制作并安放工作台，制作木镐，开挖有支撑的阶梯以取得圆石，制作石镐和熔炉，准备天然口粮，探查铁矿并带回冶炼铁镐，然后下探钻石层、开主矿道和左右分支、接近可安全采集的矿脉。工具先按真实采掘等级筛选；普通岩石优先使用石镐，天然红石、金矿等需要铁镐的障碍使用符合等级的镐，没有合格工具时保留原块并改路；石镐耐久不足时返回工作台补工具，再沿记录路线回到工作面。天然食物可通过采集与成年未命名牛、猪、羊、鸡的狩猎取得，生肉先回炉烹饪；下矿口粮按实际可恢复的净食物点计算，吃掉的食物不会继续计入储备。饥饿值下降时返营补食，确认真实食物值回升后继续。

默认钻石层取服务器世界最低高度上方 11 格；标准现代主世界为 Y=-53，旧版主世界为 Y=11。该选择用于避开基岩并减少进入最深熔岩区的机会，不代表该高度没有岩浆。高度优先读取服务器提供的 minY/height，拒绝在下界或末地执行钻石开矿。相关 API 见 [Mineflayer 官方文档](https://github.com/PrismarineJS/mineflayer/blob/master/docs/api.md)。

每一步开挖前检查站立地板、两格以上的身体空间、目标及其相邻方块；移动只沿已检查并挖通的相邻格完成，寻路器不允许额外挖掘、搭桥、跑酷或大幅坠落。未知区块不能当作空气；岩浆、水、危险地板、可能坠落的沙砾和无支撑洞穴会阻止当前路线。已知危险会触发换方向或结束该分支；挖掘和移动过程中出现的新危险会停止动作。不会挖掉机器人脚下的支撑，也不会为了露出钻石而打通相邻岩浆。

生命值、饥饿、背包空间、工具和搜索预算都有停止条件。可行时沿记录矿道撤回，随后保留同一任务并暂停，显示具体原因。补充食物/工具、清理背包或处理路线后点击 **恢复**；暂停、取消期间不继续开挖，也不会通过 AI 重规划绕过安全停止条件。检查点保留在当前运行中的任务内，退出应用或切换世界后不会自动重启旧矿道。

默认每轮最多推进 768 格矿道、执行 4,096 次挖掘或前进动作，并设两小时硬超时；沿已有路线撤退不占开矿预算。预算用于防止找不到资源时无限开挖；恢复会在已有检查点上扩展下一轮。缺少树木、食物、铁矿、受保护地块或完全被危险地形封住时，可能需要玩家补给或协助。功能实现和模拟世界回归不等于任意种子、插件服务器或用户生存世界中的成功保证。


已安装项目独立的 Java 21 和官方 Minecraft 1.21.8 本机测试服，并完成一次真实生存模式的“空背包 → 工具链 → 阶梯下矿 → 岩浆绕行 → 分支探矿 → 钻石入包 → 返回基地”。安装、重跑和重启存档见 [本地测试服指南](MINECRAFT_LOCAL_SERVER.md)，逐轮失败与最终证据见 [真实服验证记录](MINECRAFT_REAL_VALIDATION.md)。普通与高级家具住宅均已完成实际建造和家具验收；正版登录及其他版本/平台需在对应环境验证。

## 家具住宅与附魔住宅

普通任务可输入“造一座美观小屋”或 `build a furnished house`；高级任务可输入“造一座带附魔台和书架的高级小屋”或 `build an enchanting library house`。规则和混合模式均保留确定的住宅蓝图与完整家具目标，不让模型把高级房缩成简单盒子。

普通款室外主体7×9，高级款9×11。两档都有圆石墙裙、原木墙角、木地板、玻璃窗、挑檐坡屋顶、门前三格台阶、室内照明、床、工作台、箱子和熔炉。高级款再设独立附魔区，普通书架15个并保留正确空气间隔和进出通路。

执行阶段依次为背包检查、选址、材料准备、清场、地板、框架、墙、窗、屋顶、家具、收尾和验收。机器人使用临时后侧坡道和四角三阶梯施工，墙顶与地面之间逐格上下，只清除本任务实际放置的脚手架；泥土自然长成草仍保持归属，其他替换方块会保护并报错。暂停/恢复按照已建方块重新计算缺料。完成需要逐格核对屋顶、方块朝向、床/门的上下或前后半块、通道及附魔间隔，并实际开门和打开工作台、箱子、熔炉、附魔台窗口。

脚手架拆除从较低的真实安全站位逐层进行；若途中暂停，完整屋顶会保留，恢复继续拆除而不重复索要已经拆掉的泥土。房屋缺块和楼梯朝向错误仍会阻止完成。

房屋验收从机器人当前一侧靠近并打开门，确认上下门状态后再实际进出；房屋专用寻路适配使用开门后的真实碰撞净空和地板高度。Minecraft 1.21.8 的离床动作有精确版本与协议特性限定的本地兼容修复，睡眠和唤醒以原生服务端事件为准。

木材、圆石、泥土、沙子及常用木制品可通过已有采集、合成和冶炼链补齐。床和书籍等物品依赖实际羊毛、皮革、甘蔗等材料，附魔台还需要钻石和黑曜石；没有这些稀缺资源时会列出缺额并暂停，补给后点恢复。当前施工测试提供建材，另行实际验证合成、储物、冶炼、睡觉和附魔，不能据此宣称从空背包自动取得全部高级建材。

## English quick start

Open **Minecraft** in the Electron console. Connect to a Minecraft **Java Edition** server or a LAN world using its current port. Choose offline authentication only where permitted, or follow the displayed Microsoft device-code sign-in. Start in **Rules** mode; **Hybrid** mode requires an explicitly selected enabled DeskPet provider and can incur provider charges. Enter tasks in the task box, inspect observed status and logs, and use pause/resume/cancel/stop or Disconnect as needed.

The migrated engine runs in a separate process with private stdio. The app never automatically connects, starts autonomous tasks, imports source credentials, or gives the Minecraft runtime provider keys. The shipped app uses Electron's Node runtime. Bedrock and the source application's experimental protocol overrides are outside the active integration. A real vanilla 1.21.8 Normal survival run on a precommitted random seed completed from an empty inventory through natural trees, iron, food, tool replenishment, stair mining to Y=-58, 33 diamonds and a return to base. It used no placed resources or console commands during the task. Its original strict audit retains the missing natural-lava coverage; a separate real lava-bucket test passed detection, detour, continued mining and return, with all 16 independent checks passing.
